## 개요

디자인 시스템 적용은 화면을 쓰는 모든 역할의 체감 품질에 영향을 준다. 기능 변경이 없으므로 이해관계자 관심사는 "일관성·가독성·접근성·친숙함(회귀 없음)"에 집중된다.

## 이해관계자

| 이해관계자 | 관심사 | 영향 |
|---|---|---|
| 최종 사용자 — 멘티/멘토 (모바일 웹뷰) | 읽기 쉬운 타이포, 명확한 상태 색, 매끄러운 로딩/빈/오류, 친숙한 레이아웃 | 高 — 1차 체감 대상 |
| 관리자 (Admin) | 승인 큐·모니터링 등 정보 밀도 높은 화면의 가독성·상태 구분 | 中 |
| 개발자 (본인) | 토큰 기반 유지보수성, 하드코딩 제거, 기존 테스트 무손상, 다크모드 확장성 | 高 — 구현·유지 주체 |
| 접근성 (대리 이해관계자, NFR7/CC-2) | 색 단독 의존 금지(텍스트/아이콘 병기), 대비비, 포커스 링 | 中~高 — 준수 유지 |
| 파킹된 Bolt 8 작업 (bolt8-admin) | 디자인 토큰 변경이 이후 병합 시 admin 화면에도 자연 적용되도록 일관 토큰 사용 | 中 — 병합 정합 |

## 의사결정자

- **디자인 방향(브랜드 색·톤·다크모드·폰트)**: 사용자(제품 오너 겸 개발자) — intent-capture-questions.md에서 확정.
- **기술 적용 방식(토큰 구조·컴포넌트 보강)**: architect/developer 판단 + team.md/project.md 규칙 준수.

## Assumptions & Open Questions

- **[assumption]** 단일 개발자 프로젝트 — 외부 디자이너/브랜드 가이드 없음. 방향은 사용자 확정 + 기본안 제시.
- **[decided]** 브랜드 정체성 참조(무드보드/레퍼런스) 없음 — 모던·미니멀 기본안(questions Q4).
