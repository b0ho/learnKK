## 범위·수준 [Q6, NFR7]

- 목표: **기본 접근성 준수 지향** — 공식 WCAG 등급 인증은 목표 아님.
- 기준: 모바일 웹뷰(모바일 크롬/사파리) + 한국어 스크린리더(TalkBack/VoiceOver).
- 아래 체크리스트는 전 화면 공통 항목 + 화면별 특이 항목으로 구성. 구현·검증은 후속 워크플로우(설계 전용).

## 공통 체크리스트 (전 화면)

- [ ] **랜드마크/헤딩**: 각 화면 h1 1개, header/nav(하단탭)/main 랜드마크. 헤딩 계층 순서 유지.
- [ ] **폼 라벨**: 모든 입력에 label 연결(닉네임·비밀번호·**사번**·설문·개설 필드). 필수는 aria-required.
- [ ] **색+텍스트 병기**: 상태 뱃지·승인/반려·출석 상태를 색상 단독으로 구분하지 않음(텍스트/아이콘 병기).
- [ ] **대비**: 텍스트 4.5:1, UI 컴포넌트 3:1(WCAG AA 기준값 참고).
- [ ] **키보드/포커스**: 모든 상호작용 요소 Tab 접근, 논리적 포커스 순서, 가시적 포커스 링.
- [ ] **터치 타겟**: 최소 44x44px, 하단 탭·FAB·버튼 충분한 간격.
- [ ] **스크린리더 텍스트**: 아이콘 버튼(쪽지 등)에 aria-label, 안읽음 뱃지 "안 읽은 N건" 텍스트.
- [ ] **동적 알림**: 오류/성공/상태 변화 aria-live(오류=assertive, 안내=polite).
- [ ] **언어**: html lang="ko", 한국어 콘텐츠.
- [ ] **상태 표현**: 로딩(스켈레톤/aria-busy), 빈, 오류(재시도) 상태가 스크린리더에 전달.

| 화면 | 접근성 특이 항목 |
|---|---|
| 1 모임 목록 | 필터 ToggleGroup 상태 aria-pressed; 카드=link, 포커스 순서 검색→필터→카드; 스켈레톤 aria-busy |
| 2 모임 상세 | 정보 dl; 하단 고정 CTA aria-disabled(정원마감/비로그인); 신청 결과 aria-live |
| 3 사전설문(②후) | label-input 연결, 라디오 fieldset/legend; ②이전 진입 시 안내 텍스트 |
| 4 멘티 참여 중 | 진행률 aria-valuenow/valuemin/valuemax(출석 세션/전체); 내부 탭 tablist/tab/tabpanel; 설문 미응답 배너 |
| 5 멘토 관리 | 세션 목록 list; [변경] 다이얼로그 포커스 트랩; 세션 추가/변경 결과 aria-live |
| 6 관리자 모니터링 | 승인 큐 4종 액션 링크(건수 텍스트 병기); 반려 다이얼로그 포커스 트랩·사유 textarea label |
| 7 모임 개설 | 필드 label·aria-required; 문항 빌더 추가/삭제 버튼 라벨; 검증 오류 aria-invalid |
| 8 쪽지함 | 목록 list; 안읽음 상태 텍스트; 스레드 진입 링크 라벨 |
| 9 로그인/가입·내정보 | 폼 label(사번 포함); 로그인 실패 aria-live(계정 존재 비특정); 중복 오류 필드 aria-invalid |
| 10 출석 팝업 | role=dialog·aria-modal; 포커스 트랩; ESC/[나중에] 닫기; 제목 aria-labelledby; 상태 aria-live |

## rev2 관련 접근성 유의

- **사번 필드(화면9)**: 라벨 명시, 숫자 입력 시 inputmode 적절히, 중복 오류 안내.
- **출석 팝업(화면10)**: 모달 접근성(포커스 트랩·복귀)이 핵심 — 세션 시각 트리거 팝업이 스크린리더 사용자에게도 명확히 안내되도록.
- **세션 일정(화면5)**: 날짜/시간 입력 컨트롤 키보드 접근, 변경 결과 라이브 안내.

## Assumptions & Open Questions

- 실제 접근성 검증(스크린리더 실사용·대비 측정)은 구현/후속 워크플로우에서 수행 — 이 체크리스트는 설계 기준.
- 공식 WCAG 등급 인증은 범위 밖(NFR7). 필요 시 추후 별도 워크플로우로 상향 가능.
