## 횡단(cross-cutting) 스토리 — 다중 Unit

- **관리자 승인(US-2.2 ①, US-3.4 모집확정, US-6.1 ②, US-7.2 ④, US-7.3 ③):** 승인 **액션**은 소유 도메인 Unit(U3의 상태전이, U5의 수료 판정), 승인 **큐 조회**는 U9. 두 Unit이 협력(액션=소유 Unit, 조회=U9).
- **US-2.3 멘토 운영 허브:** U3 화면이 U4(신청자)·U8(사전설문 응답) read 조합(ADR-007).
- **US-3.5 멘티 현황:** U4 화면이 U5(세션 일정) read 조합.
- **횡단 AC(CC-1 에러계약·CC-2 접근성·CC-3 목록상태):** 전 Unit 상속(U1 계약·공통 UI 기반).

## Unit 내 스토리 구현 순서(참고 — Unit 내부 자연 순서, 빌드 배치 아님)

- **U2:** US-1.1(가입) → US-1.2(로그인·RBAC) → US-1.3(사번 중복) → US-1.4(프로필).
- **U3:** US-2.1a/2.1b(개설·문항) → US-2.2(①) → US-3.1(목록)/US-3.4(모집확정) → US-6.1(②) → US-2.3(허브) → US-7.3(③).
- **U4:** US-3.2(신청) → US-3.3(취소) → US-3.5(현황).
- **U5:** US-6.2(세션) → US-6.3(출석) → US-7.1(자동판정) → US-7.2(④)/US-7.4(현황).
- **U6:** US-4.1a → US-4.1b → US-4.2 → US-4.3.
- **U7:** US-5.1.
- **U8:** US-3.6(사전설문 응답) → US-8.1(과정설문) → US-8.2(피드백 열람).
- **U9:** US-9.1(승인 큐) → US-9.2(모니터링). (US-9.3 Won't.)

## 커버리지 검증

- **모든 스토리 배정:** US-1.1~US-9.2 전 30개 Must 스토리가 Unit에 매핑됨. US-9.3은 Won't(범위 밖)로 명시 — 미배정 아님.
- **모든 Unit에 스토리:** U2~U9 각 Unit이 ≥1 스토리 보유. U1(Contracts&Kernel)은 사용자 스토리 직접 구현이 아니라 **전 스토리가 상속하는 계약·타입**을 전달(스토리 실행 Unit 아님, 기반 spec) — 정상.
- **orphan 없음:** 배정 안 된 스토리·스토리 없는 도메인 Unit 없음.
