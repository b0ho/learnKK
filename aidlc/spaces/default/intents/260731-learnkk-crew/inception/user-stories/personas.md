## 공통 컨텍스트 (세 페르소나)

- 모바일 웹뷰 우선(최신 모바일 크롬/사파리), 한국어 단일, 기본 접근성 지향(NFR1/NFR7).
- **푸시·이메일·SMS 없음(FR5.2)**: 모든 상태 변화(승인·반려·모집확정·모임취소·수료확정·새 쪽지)는 **재접속·새로고침 시 인앱 현황/뱃지로 능동 확인**한다. 이 제약이 각 페르소나의 "내 현황" 화면 필요성을 만든다.

## P1. 멘토 (Mentor) — 모임 운영자

- **역할**: 러닝 크루를 개설하고 학습 기간 동안 운영하는 주체.
- **목표**: 계획한 주차별 학습 활동을 기간 내 전부 진행·완료하고, 멘티가 잘 따라오도록 자료·공지·소통을 체계적으로 관리한다.
- **페인포인트(현행)**: 공지·자료·출석·수료를 wiki와 수작업으로 흩어 관리해 부담이 크고 누락이 잦다.
- **컨텍스트**: 모바일 웹뷰. 개설 시 주제·기간·정원·진행방식·사전설문 문항을 직접 구성. ②시작 이후 주차별 **수업 세션의 날짜·시간을 지정·변경**해 멘티에게 공유(주차당 복수 세션 가능). 운영 허브에서 자기 모임 상태·세션 일정·신청자 명단과 (②시작 후) 사전설문 응답을 확인. 멘티 피드백을 확인. (모임 완료 인정 신청 없음 — 종료 시 관리자가 ③ 직접 처리, rev3)
- **권한 경계**: 자기 모임의 개설·자료(게시글)·공지·**세션 일정 지정·변경**; **자기 모임 신청자·사전설문 응답 열람**. **멘티 수료·모임 완료 여부는 판정하지 않는다**(관리자 몫).
- **우선순위**: High (모임 콘텐츠·진행의 생산자).

## P2. 멘티 (Mentee) — 학습 참여자

- **역할**: 열린 모임을 탐색·신청하고 주차별로 참여·출석하는 학습자.
- **목표**: 관심 주제의 모임을 쉽게 찾아 신청하고, 기간 내 출석율 80% 이상을 달성해 수료한다.
- **페인포인트(현행)**: 어떤 모임이 열리는지, 내 신청·진행·출석 상황이 어떤지 한눈에 보기 어렵다.
- **컨텍스트**: 모바일 웹뷰. 가입 시 닉네임·비밀번호·**사번** + 관심사 해시태그·한 줄 소개. 신청은 선착순(설문은 ②시작 후 응답). 예정 세션 시간에 **시스템 팝업으로 직접 출석 체크(self check-in)**. **내 현황 화면에서 신청 상태·세션 일정·출석 세션/전체 세션·수료 여부를 스스로 추적**. 종료 후 과정 설문 제출.
- **권한 경계**: 신청/취소(모집기간·시작대기 한정), 사전설문 응답(②시작 후), 세션별 출석 체크, 자료·공지 열람, 과정 설문 제출, 본인 현황 조회.
- **우선순위**: High (핵심 수요자, 수료 성공 지표의 주체).

## P3. 시스템 관리자 (System Admin) — 감독·품질 관리자

- **역할**: 전체 모임을 감독하고 4개 지점에서 승인하며 품질을 관리하는 운영 주체.
- **목표**: 전체 현황을 한눈에 모니터링하고, 개설·시작·완료·수료 승인을 통해 품질을 통제하며, 필요 시 멘토/멘티와 직접 소통한다.
- **페인포인트(현행)**: 전체 현황 모니터링·품질관리 수단이 없고, 특이사항 발생 시 소통 채널이 부족하다.
- **컨텍스트**: 모바일 웹뷰. 4지점 승인(①개설 ②시작 ③모임완료(종료 시 직접 처리) ④멘티수료), 모집 마감 확정, 멘티 피드백 열람, 관리자↔멘토/멘티 쪽지. [rev3: ③은 멘토 신청 없이 관리자 직접]
- **권한 경계**: 승인 큐 처리, 모니터링 열람(전 모임), 모집 확정, 쪽지(전원 대상). (수료는 시스템 자동 판정을 승인하여 확정.)
- **우선순위**: High (품질 게이트·감독 주체, 전 여정을 가로지르는 cross-cutting 액터).

## 페르소나 관계·우선순위

- 세 페르소나는 하나의 플랫폼을 공유하며, 여정 상에서 순차·교차한다: 멘토(개설·진행) → 관리자(승인 게이트) → 멘티(신청·출석) → 시스템(수료 자동판정) → 관리자(수료 승인) → 멘토(피드백 확인).
- 우선순위 랭킹: 멘티·멘토가 핵심 가치 생산·소비의 양축(공동 1순위), 관리자는 품질·감독의 필수 cross-cutting(1순위 동급, 게이트 소유).

## Assumptions & Open Questions

- **역할 겸직**: 한 계정이 어떤 모임에선 멘티, 다른 모임에선 멘토가 될 수 있는지(FR1.5 역할기반)는 미확정 — 겸직 허용 시 역할 전환 내비게이션이 화면 설계에 영향. **application-design에서 확정**(design 기고).
