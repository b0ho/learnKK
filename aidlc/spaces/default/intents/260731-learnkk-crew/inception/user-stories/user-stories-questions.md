# User Stories — Story Plan + 인터뷰 질문지 (learnKK / 런크크)

## Story Plan (초안 계획)

- **페르소나 접근**: 확정된 3역할을 페르소나로 정식화 — 멘토(mentor), 멘티(mentee), 시스템 관리자(system admin). 각 페르소나에 목표·페인포인트·컨텍스트·우선순위.
- **스토리 형식**: "As a [페르소나], I want [목표], so that [가치]" + **Given/When/Then 인수기준**(inception 규칙) + INVEST 준수 + MoSCoW 우선순위 + 의존성.
- **우선순위**: requirements 기반으로 각 스토리에 MoSCoW(Must/Should/Could/Won't) 부여. MVP 경계는 delivery-planning에서 확정하되 스토리 우선순위가 근거가 됨.
- **분해 접근(초안)**: 여정(workflow) 기반 에픽 + 관리자 cross-cutting 에픽. 후보 에픽: ① 계정·프로필, ② 모임 개설·승인, ③ 탐색·모집·신청, ④ 주차 진행(게시글형 자료실·공지), ⑤ 쪽지, ⑥ 출석, ⑦ 수료·완료, ⑧ 과정설문·피드백, ⑨ 관리자 모니터링(cross-cutting).

아래 질문으로 계획을 확정합니다. 각 `[Answer]:`에 보기 문자를 적어주세요(복수 선택 문항 표시). 직접 서술은 `X. 기타`.

## Revision Clarifications (gate cycle 2)

### RQ1. "사전설문은 운영자의 2승인 이후 진행" 의 의미
현재 관리자 승인은 ①개설 ②시작 ③멘토완료 ④멘티수료입니다. "2승인 이후 사전설문 진행"이 어떤 뜻인가요?
- A. 사전설문(신청 설문)은 현재대로 **모집중(①개설 승인 이후)**에 멘티가 신청하며 응답한다 — 변경 없음(오해였음)
- B. **신설**: 모임 개설·설문 구성 후 관리자의 **2차 승인(설문/모집 개시 승인)**을 받아야 비로소 모집·사전설문 응답이 시작된다 (즉 ①개설승인 → 관리자 2차 승인 → 모집/설문 시작). 승인 지점이 늘어남.
- C. 멘토가 만든 **사전설문 문항 자체를 관리자가 승인**한 뒤에만 신청자에게 노출된다(설문 내용 검수 승인).
- X. 기타 (직접 서술)

[Answer]: X. 사전설문 응답을 ②시작 승인 이후에 진행하도록 변경(신청과 분리)

### RQ2. 출석·수료 80% 분모 (주차별 수업이 여러 번 가능해짐)
"주차별 수업은 여러 번 있을 수 있다"에 따라 출석율 80%의 분모를 무엇으로 할까요?
- A. **전체 예정 수업(세션) 회수** 기준 — 출석율 = 출석 세션 수 / 전체 예정 세션 수, 80% 이상 수료
- B. **주차 기준** — 한 주차에 여러 세션이 있어도 그 주차에 1회 이상 출석하면 해당 주차 출석 인정, (출석 주차 수 / 전체 주차 수) ≥ 80%
- C. 기타 (직접 서술)

[Answer]: A. 전체 예정 세션 회수 기준(출석 세션/전체 세션 ≥ 80%)

### RQ3. (확인) 출석 주체·기록 단위
피드백상 "멘토가 출석 체크를 진행"으로 이해했습니다. 맞나요?
- A. 맞음 — **멘토가** 각 세션에서 멘티 출석/결석을 표시(멘티 self check-in 폐지)
- B. 멘토가 출석 창을 열고 **멘티가 self check-in**(기존 유지)
- X. 기타 (직접 서술)

[Answer]: X. 멘티가 예정 세션 시간에 시스템 제공 팝업으로 직접 self check-in(멘토는 세션 일정 지정·변경 담당)
