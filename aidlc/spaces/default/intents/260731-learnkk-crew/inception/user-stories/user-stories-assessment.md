# User Stories Assessment — learnKK (런크크)

## Decision

**Execute** — 이 프로젝트에 user stories는 높은 가치를 더한다.

## Rationale

learnKK는 명확히 사용자 대면(user-facing) 플랫폼이며, 서로 다른 목표와 워크플로우를 가진 **3개 페르소나**(멘토·멘티·시스템 관리자)가 하나의 시스템을 공유한다. 개설→승인→모집→주차 진행→출석→수료→피드백으로 이어지는 다단계 여정과, 관리자 4지점 승인·80% 출석 자동 수료 판정 같은 **복잡한 비즈니스 로직**이 존재한다. 또한 팀 3인이 기능 수직 슬라이스로 **독립 병렬** 구현하므로, INVEST 기반 스토리와 명확한 인수기준(Given/When/Then)이 슬라이스 경계·인터페이스 계약·테스트 기준을 정렬하는 데 직접 기여한다.

## Factors Considered

- **프로젝트 유형**: greenfield, 사용자 대면 웹 플랫폼 (user stories 적합).
- **페르소나 다수**: 멘토/멘티/관리자 3역할, 각기 다른 목표·권한.
- **복잡도 신호**: 모임 상태 머신, 관리자 4지점 승인, 출석·80% 수료 자동 판정, 게시글형 자료실, 사전설문, 쪽지.
- **팀 협업**: 독립 병렬 3인 → 스토리가 슬라이스 배분·인터페이스 계약의 기준선.

## Where Stories Add the Most Value

- 역할 교차 워크플로우(개설→승인→모집→진행→수료)의 단계별 actor·행위·가치를 명시.
- 관리자 4지점 승인과 출석/수료 경계값(80%) 같은 비즈니스 규칙을 테스트 가능한 인수기준으로 고정.
- MoSCoW 우선순위로 delivery-planning의 MVP 경계·3인 배분 근거 제공.
