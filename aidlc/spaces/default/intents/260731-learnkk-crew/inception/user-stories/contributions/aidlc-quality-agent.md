## Contribution

전반 평가: 대부분의 인수기준이 유효한 Given/When/Then 형식이고 US-7.1(79/80/81)·US-6.2(출석창 개폐)·US-3.2(정원 마감)·US-7.3(권한 경계) 등 핵심 경계가 명시되어 있어 테스트 가능성 기반이 양호하다. 아래는 pass/fail 검증을 막는 구체적 결함과 통합 가능한 보강 제안이다. (제안 문구는 삽입/치환용 확정 G/W/T 초안이며, 임계값이 하류 이월(OQ)인 경우 그 사실을 함께 표기.)

### C1. US-3.1 — 모호·비게이팅 성능 문구가 Must 인수기준에 혼입 (inception 규칙 위반 소지)
- 문제: "Given 목록 응답, Then **체감** 1~2초 이내로 표시된다(NFR3 가이드)"는 (a) "체감"이 주관적이고, (b) 측정 방법(p50/p95, 부하 조건)이 없으며, (c) requirements NFR3 자체가 "엄격 SLA 아님"이라 명시. 인수기준(pass/fail 게이트)으로는 검증 불가.
- 제안: 이 문장을 인수기준에서 **제거**하고 스토리 노트로 강등하거나, 성능 검증을 performance-validation/nfr-requirements로 명시 이월. 기능 AC는 다음만 유지:
  - `Given 모집중 모임이 존재, When 멘티가 목록을 조회, Then 각 모임이 주제·기간·정원·모집현황과 함께 반환된다.`
  - (노트) 응답시간 목표(NFR3 가이드, 비게이팅)는 performance-validation에서 부하·백분위 조건과 함께 검증.

### C2. US-3.2 — 선착순 동시성 경계·중복신청 미커버 (정원 경계의 핵심 결함)
- 문제: FR3.3=선착순인데 "마지막 잔여 1석에 동시 신청" 경합과 "동일 멘티 중복 신청"이 없다. line coverage로는 잡히지만 team-practices가 요구한 도메인 분기(branch/시나리오) 커버리지 대상이다.
- 추가 제안:
  - `Given 정원 N, 현재 접수 N-1건(잔여 1석), When 두 멘티가 동시에 신청 제출, Then 정확히 1건만 접수되고 나머지는 마감 안내를 받는다(초과 접수 0).`
  - `Given 이미 신청한 멘티, When 같은 모임에 재신청, Then 중복 신청으로 거부된다(정원 이중 점유 없음).`

### C3. US-3.3 — 상태 사각지대(모집확정~②승인 전 '시작대기') 미정의
- 문제: 취소 허용은 "모집기간 중", 거부는 "시작(②) 이후"만 규정. **모집확정 후 시작대기 상태**(② 이전)에서의 취소 가능 여부가 공백 → 판정 불가.
- 추가 제안:
  - `Given 모집확정으로 시작대기 상태(② 승인 전), When 멘티가 취소 시도, Then <허용|거부>로 처리된다.` — 허용/거부 방향을 리드가 확정(FR3.5 문언상 "시작(②) 이후 이탈 불가"이므로 시작대기까지는 허용이 자연스러우나 명시 필요).

### C4. US-7.1 — 출석율 임계 비교의 반올림/비교 규칙 미정의 (79/80/81은 예시일 뿐 실경계 아님)
- 문제: 산식이 `A/N`인데 실제 N에서 정확히 80%가 안 나오는 경우가 흔하다(예 N=6: A=4→66.7%, A=5→83.3% — 80% 경계값 자체가 도달 불가). "79%/80%/81%"만으로는 비교·반올림 규칙이 불명확해 결정적 테스트를 작성할 수 없다.
- 치환 제안:
  - `Given 계획 주차 N·출석 A, When 판정, Then 수료후보 판정은 (A/N) ≥ 0.80 (부동소수 비교는 명시 규칙으로 고정; 예: 반올림 없이 A*100 ≥ 80*N 정수 비교) 로 이루어진다.`
  - `Given N=5,A=4(정확히 80%), When 판정, Then 충족.` / `Given N=5,A=3(60%), Then 미충족.` / `Given N=6,A=5(83.3%), Then 충족.` — 정수 N에서 실제로 도달 가능한 경계값을 예시로 사용.

### C5. 상태기계 불법 전이 negative 커버리지 부재 (① → ② → ③/④ + 반려/취소)
- 문제: 각 승인 스토리(US-2.2/6.3/7.2/7.3)는 정상 전이만 검증. 잘못된 상태에서의 승인·이중 승인·순서 위반이 어디에도 없다. 상태기계는 negative 전이 테스트가 핵심.
- 추가 제안(횡단 기준 — US-2.2/6.3/7.2/7.3에 각각 부여하거나 상태기계 공통 스토리로):
  - `Given 모집중이 아닌 모임, When 관리자가 ②시작 승인 시도, Then 잘못된 상태 전이로 거부된다(409/유효성 오류).`
  - `Given 이미 ①승인된 모임, When 재차 ①승인, Then 멱등 또는 거부로 처리되어 중복 전이가 발생하지 않는다.`
  - `Given 반려된 모임(US-2.2), When 멘토가 수정 후 재신청, Then <재승인 큐 재진입|불가>가 명시된다.` — 반려의 후속 경로가 현재 공백.
  - `Given 취소 상태(US-3.4), Then 이후 어떤 승인/진행 전이도 불가한 종료 상태다.`

### C6. US-1.2 — 안티-중복 신호: 비노출은 검증 가능하나 TTL 파기는 임계값 부재로 경계 테스트 불가
- 문제: "TTL 경과 → 파기"는 보관창 값이 OQ5로 이월되어 미정 → 파기 직전/직후 경계 테스트를 작성할 수 없다. 비노출(UI·API·로그·에러) 검증은 훌륭하며 유지.
- 추가/보강 제안:
  - `Given 신호가 저장됨, When 로그·에러 응답·API 응답·UI를 관측, Then 원본 값이 어디에도 나타나지 않고 salted hash/마스킹만 존재한다.` (유지)
  - (이월 명시) `Given 보관창 T 경과, When 파기 배치/트리거 실행, Then 해당 신호 레코드가 제거된다.` — **T 값과 파기 트리거 방식은 nfr-requirements/functional-design에서 확정해야 경계(T-ε/T+ε) 테스트 작성 가능**을 스토리 노트에 명기.

### C7. US-4.1 — 첨부 형식 화이트리스트 거부·크기 경계 미커버
- 문제: 크기 초과 오류는 있으나 (a) 허용되지 않는 형식(화이트리스트 외) 업로드 거부가 없고, (b) 크기 경계(상한 정확히 == / +1B)가 없다. 상한값은 OQ4 이월이나 형식 거부는 지금 표현 가능.
- 추가 제안:
  - `Given 화이트리스트 외 형식 파일, When 업로드, Then 형식 불허 오류(400)가 표준 에러 스키마로 반환된다.`
  - (이월 명시) 크기 경계 테스트(상한 정확값/+1)는 최종 상한 확정(OQ4) 후 작성.

### C8. 열람·소통 권한 negative 누락 (US-4.2 / US-5.1)
- US-4.2: 비참여자의 게시글 열람 시도가 공백. 추가: `Given 해당 모임 비참여 사용자, When 게시글 열람 시도, Then 403으로 거부된다.`
- US-5.1: 403은 있으나 "권한 있는 상대"의 정확한 경계 미정의. 추가: `Given 멘토가 자기 모임에 속하지 않은 멘티, When 쪽지 전송, Then 403으로 거부된다.` (관리자는 전원 허용 대비.)

### C9. 전역 에러 스키마·상태코드 일관성 (NFR8 계약 테스트 필수)
- 문제: 표준 에러 스키마 `{code,message,details}`는 US-1.1에만 명시. 그러나 US-1.3(400)·US-3.2(마감)·US-5.1(403)·US-4.1(크기) 등 다수 오류 경로가 스키마·상태코드를 assert하지 않는다. team-practices의 **OpenAPI 계약 테스트**는 각 오류가 스키마·코드를 준수함을 검증하므로 AC에 일관되게 걸려야 한다.
- 제안: 스토리별 반복 대신 **횡단 인수기준**을 추가 — `Given 임의의 오류 응답, Then 본문은 {code,message,details} 스키마를 따르고 상태코드는 NFR8 규약(검증 400 / 인증 401 / 인가 403 / 미존재 404)을 준수한다.` 각 negative AC는 이를 상속.

### C10. NFR 추적성 갭 (Must 스토리↔NFR 매핑)
- FR 추적성은 모든 Must가 Ref를 가져 양호. 다만 NFR 매핑이 US-1.1(NFR6/8)·US-3.1(NFR3)로 한정. NFR7(접근성: 폼 라벨·색 대비·키보드 포커스)·NFR1(모바일 웹뷰 뷰포트)을 검증하는 인수기준/노트가 전무.
- 제안(설계 전용 스코프 내, 비게이팅 노트 수준으로 충분): 관련 UI 스토리(US-1.3, US-3.1, US-3.2 등)에 노트로 "접근성 기본(폼 라벨/포커스/대비)·모바일 웹뷰 검증은 functional-design/구현 워크플로우에서 확인" 이월 참조를 명기해 추적 고아를 방지.

### C11. US-6.2 — 출석 체크 주체 권한 negative
- 문제: 창 개폐 경계는 우수하나 "누가 체크하는가"의 negative 부재. 추가: `Given 해당 모임 비참여자(또는 멘토), When 출석 체크 시도, Then 거부된다.` (self check-in 주체를 참여 멘티로 한정 검증.)

## Positions

- AGREE: US-7.1 79/80/81 경계 명시 — 수료 자동판정의 핵심 분기를 경계값으로 못박은 점은 team-practices의 시나리오 커버리지 요구와 정합적이며 모범적이다. (단 C4의 반올림/비교 규칙 보강 필요.)
- AGREE: US-6.1/6.2 출석창 개폐 경계·1회 기록 멱등 — 창 닫힘 시 거부·중복 체크 1회 처리로 pass/fail 검증 가능.
- AGREE: US-7.3 멘토 권한 경계(멘티 수료 판정 불가) 인수기준화 — 권한 boundary를 스토리에 명시한 점 유효(단 "권한 없음"을 403 호출 시도로 구체화 권장).
- AGREE: Q4=A(4지점 승인 독립 스토리) — 트리거·상태전이가 달라 개별 테스트 가능성이 높아지는 올바른 분해.
- OBJECT: US-3.1 "체감 1~2초 이내" 인수기준 — 주관·비측정·비SLA 문구가 Must AC에 있어 inception 모호어 금지 규칙에 저촉. 제거 또는 성능 스테이지 이월 필요(C1).
- OBJECT: 상태기계 정상 전이만 검증 — 불법/이중/역순 전이와 반려·취소 종료성의 negative 인수기준 부재는 상태기계 품질 게이트의 사각지대(C5).
- OBJECT: 오류 응답 스키마/상태코드가 US-1.1에만 명시 — 계약 테스트(NFR8) 대상 오류가 다수 미검증. 횡단 인수기준으로 고정 필요(C9).
- OBJECT: US-3.2 선착순 동시성·중복신청 경계 누락 — 정원 무결성의 핵심 경합 경로가 미커버(C2).
