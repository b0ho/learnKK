## Contribution

리드 초안(personas.md / stories.md)을 UX·페르소나 충실성 관점에서 적대적으로 검토했다. 여정 정합성은 견고하나, **사용자가 "지금 내 상태가 어떤지" 확인하는 화면·피드백 경로**가 여러 곳에서 비어 있다. 모바일 웹뷰 + 푸시 없음(FR5.2) + 한국어 단일 + NFR7 기본 접근성이라는 컨텍스트에서, 아래 항목이 스토리로 승격되거나 인수기준에 반영되어야 한다. 모두 설계-전용 범위(화면/상태/피드백 명세)이며 구현·배포는 건드리지 않는다.

### A. 페르소나 보강 (personas.md)

- **P1/P2/P3 공통 — 모바일 웹뷰 세션·알림 컨텍스트 누락**: "푸시·이메일 없음(FR5.2)"은 쪽지뿐 아니라 **모든 상태변화(승인·반려·모집확정·모임취소·수료확정)**에 적용된다. 즉 세 페르소나 전원이 "인앱 뱃지/현황을 능동적으로 확인해야만 알 수 있다"는 강한 UX 제약을 공유한다. 각 페르소나 **컨텍스트**에 "상태 변화는 푸시가 아니라 재접속·새로고침 시 인앱 현황/뱃지로 확인" 한 줄을 추가할 것을 제안한다.
- **P2 멘티 — 목표 대비 추적 수단 부재**: 멘티 목표가 "출석율 80% 이상 달성해 수료"인데, 페르소나에도 스토리에도 **본인 출석율/수료 진행을 스스로 확인하는 경로**가 없다(US-9.2는 관리자 전용). 멘티 컨텍스트에 "진행 중 내 출석율·남은 주차를 확인" 추가.
- **P1 멘토 — 신청자·사전설문 응답 열람 권한 미기재**: 멘토가 사전설문 문항을 구성(US-2.1)하지만, **신청자 목록과 그 응답을 열람하는 권한**이 권한 경계에 없다. "자기 모임 신청자·사전설문 응답 열람"을 P1 권한 경계에 추가.
- **역할 겸직 여부 미정의**: 한 계정이 어떤 모임에선 멘티, 다른 모임에선 멘토가 될 수 있는지가 페르소나에 불명확(FR1.5 역할기반). 겸직이 허용되면 **역할 전환 내비게이션**이 화면 설계에 영향을 준다. 최소한 노트로 "겸직 가정 여부는 application-design에서 확정" 명시 제안.

### B. 누락 스토리 (신규 제안 — 모두 사용자 노출 화면/흐름)

- **US-1.4 로그인·세션 유지 (Must)** — 현재 US-1.1은 가입 직후 자동 로그인만 다루고 **재접속 로그인**이 없다. 모바일 웹뷰는 백그라운드 전환·탭 종료로 세션이 끊기기 쉬워 재로그인 흐름이 필수.
  - Given 기존 사용자, When 닉네임+비밀번호로 로그인, Then 인증되어 홈으로 진입한다.
  - Given 잘못된 자격정보, When 로그인, Then 원인 미특정(계정 존재 여부 비노출)한 표준 에러가 표시된다. (보안·UX 겸용)
- **US-3.5 멘티 "내 신청/내 모임" 현황 (Must)** — 신청 후 상태(접수/①승인/반려/모집확정/시작/취소)를 확인할 화면이 없다. 푸시가 없으므로 이 화면이 멘티의 유일한 상태 확인 통로.
  - Given 신청 이력 보유 멘티, When 내 현황 조회, Then 신청한/참여 중인 모임이 각 상태·다음 액션(예: 출석 체크 가능)과 함께 목록으로 표시된다.
  - Given **모임이 정원 미달로 취소(US-3.4)**, When 멘티가 현황 조회, Then 해당 모임이 "취소됨"으로 표시된다. (rejection/cancel 가시성 — 현재 어디에도 없음)
- **US-2.3 멘토 "내 모임" 홈 + 신청자·사전설문 응답 열람 (Must)** — 멘토가 자기 모임 상태·현 주차·신청자 명단과 사전설문 응답을 보는 화면. US-2.1(개설)과 US-6.1(주차 진행) 사이의 운영 허브가 비어 있다.
  - Given 멘토, When 내 모임 조회, Then 모임별 상태·모집현황·현 주차·완료인정 신청 가능 여부가 표시된다.
  - Given 신청자 존재, When 신청자 상세 열람, Then 각 신청자의 사전설문 응답이 표시된다.
- **US-7.4 멘티 수료 결과·진행 확인 (Must)** — ④승인(US-7.2) 후 멘티가 **본인이 수료했는지**를 확인할 경로가 없다. 진행 중에는 현재 출석율/80% 달성 여부도 함께.
  - Given 진행 중, When 내 진행 조회, Then 현재 출석 주차/계획 전체 주차와 80% 대비 현황이 표시된다.
  - Given ④수료 승인 완료, When 멘티가 조회, Then "수료 확정"이 표시된다.

### C. 인수기준 보강 (기존 스토리)

- **US-3.1 / US-3.2 (모집 마감 가시성)**: 목록·상세에서 정원 마감을 **텍스트 라벨("모집마감")과 신청 버튼 비활성**으로 시각화하고, 색상만으로 상태를 구분하지 않는다는 AC 추가(NFR7 색 대비·비색상 의존).
- **US-2.2 (반려 사유 가시성)**: "멘토가 확인할 수 있다"를 구체화 — 반려 사유가 멘토의 내 모임 현황(US-2.3)에서 **텍스트로 열람**되고, 재개설/수정 다음 동작이 안내된다.
- **US-5.1 (쪽지)**: 미확인 뱃지에 **스크린리더용 텍스트 대체(예: "안 읽은 쪽지 3건")**를 두어 색상/숫자 배지 단독 의존을 피한다는 AC 추가.
- **US-8.1 (과정 설문 노출 타이밍)**: 설문 진입 지점이 불명확 — "참여 멘티에게 완료 시점 내 현황(US-3.5/7.4)에서 설문 제출 진입점이 노출된다" AC 추가.
- **공통 상태 화면(US-3.1, 9.1, 9.2 등 목록형)**: 빈 상태(empty state)와 오류/로딩 상태를 인수기준에 명시 — "목록이 비면 안내 문구와 다음 행동(예: '열린 모임이 없습니다')을 표시", "로딩 중 지연 표시, 실패 시 재시도 안내". 모바일·느린 연결 대비.

### D. 접근성 posture (NFR7 — cross-cutting)

스토리 전반에 접근성 흔적이 전혀 없다. 개별 스토리마다 반복하기보다, **stories.md 상단 노트 또는 별도 cross-cutting AC 블록**으로 한 번 선언하고 각 화면 스토리가 상속하도록 제안한다. 최소 항목: 모든 폼 입력에 라벨 연결, 상태/뱃지는 색상+텍스트(또는 아이콘) 병기, 키보드/포커스 이동 가능, 모바일 터치 타겟 충분한 크기, 한국어 스크린리더 라벨. (공식 WCAG 등급 인증은 목표 아님 — NFR7과 일치.)

## Positions

- AGREE: 여정 기반 에픽 ①~⑨ 구조 — requirements FR 그룹과 정렬되어 흐름 추적성이 좋다.
- AGREE: 관리자 4지점 승인을 독립 스토리로 분리 — 트리거·상태전이가 달라 화면·피드백 설계 단위로도 타당하다.
- AGREE: 경계값 인수기준(정원 마감, 출석창 개폐, 79/80/81%) — 사용자 노출 edge 상태를 명확히 규정한다.
- OBJECT: 멘티 자기 현황 화면 부재(US-3.5/US-7.4 미존재) — 페르소나 핵심 목표(신청 상태 파악·80% 수료)를 충족할 화면이 없어 여정이 끊긴다.
- OBJECT: 로그인·세션 스토리 부재(US-1.4 미존재) — 자동로그인만으로는 모바일 웹뷰 재접속을 설계할 수 없다.
- OBJECT: 멘토 신청자·사전설문 응답 열람 경로 부재(US-2.3 미존재) — 멘토가 구성한 설문 결과를 볼 스토리·권한이 빠져 있다.
- OBJECT: 상태변화 가시성(반려·모임취소·수료확정)이 푸시 없음 컨텍스트에서 인앱 현황으로 어떻게 도달하는지 미규정 — rejection/cancel 통지 가시성 공백.
- OBJECT: 접근성(NFR7)·빈/오류/로딩 상태가 인수기준에 전무 — 모바일·기본 접근성 요구가 스토리에 반영되지 않았다.
