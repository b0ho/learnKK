# Build vs Buy — learnKK (런크크)

<!-- 구축 방식 결정. 출처: 사용자 답변(Q4) + intent 초기 범위 신호. -->

## 결정: Build (자체 구축, 전부 로컬)

사용자가 확정함 (출처: 답변 Q4=A, intent Initial Scope Signal):

- learnKK는 **자체 구축(build)** 한다.
- **전부 로컬 환경**에서 개발·실행한다.
- **AWS 등 외부 SaaS/서드파티 서비스는 사용하지 않는다.**
- 배포·연계는 이번 범위 밖(향후 별도 워크플로우로 분리).

## 근거

- 학습·파일럿 목적과 3인 팀의 직접 구현 실습 맥락 (intent Initiative Trigger, Target Customer) — 자체 구축이 학습 가치와 통제권 측면에서 부합.
- 외부 서비스 의존을 배제해 로컬에서 완결적으로 개발·검증 가능.
- 요구 기능(모임 운영·출석·쪽지·수료)은 특별한 외부 전용 서비스 없이 일반적인 웹 애플리케이션 스택으로 구현 가능.

## 함의 (Implications)

- 인증(닉네임+비밀번호), 데이터 저장, 파일(자료실) 업로드, 메시징(쪽지) 등은 모두 로컬 실행 가능한 컴포넌트로 설계한다. (구체 스택은 application-design에서 결정)
- 외부 인증·스토리지·알림 SaaS는 채택하지 않는다.
- 오픈소스 라이브러리/프레임워크는 로컬에서 실행 가능한 범위에서 사용할 수 있다(자체 구축의 일부로 간주).

## Assumptions & Open Questions

- 구체적인 언어·프레임워크·저장소(예: DB) 선택은 이 단계의 범위가 아니며 application-design에서 확정한다.
