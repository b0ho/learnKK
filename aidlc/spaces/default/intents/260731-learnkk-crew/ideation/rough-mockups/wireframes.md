모바일 웹뷰(세로) 기준 저충실도 와이어프레임. `intent-statement.md`의 3역할·핵심 여정, `scope-document.md`의 In-scope, `intent-backlog.md`의 proto-Unit을 화면으로 매핑한다. 온라인 클래스/코호트 러닝 결, 카드형(썸네일 없음), 상태 뱃지·해시태그 필터·기간·정원 표시(Rough Mockups Q2·Q3).

## 정보 구조(IA) — 역추천 제안

요건 기반으로 아래 구조를 제안한다(Rough Mockups Q1: 역추천 요청). intent의 3탭 골격을 유지하되, 쪽지(cross-cutting)는 탭이 아니라 **전역 헤더 아이콘**으로 빼는 것을 권장(3탭 유지 + 어디서나 접근).

- **전역 헤더:** 좌 로고/제목 · 우 [쪽지] 아이콘(안 읽음 뱃지)
- **하단 3탭:**
  - 탭1 **모임** — 전체 모임 탐색(공통)
  - 탭2 **내 러닝** — 역할 적응형: 멘티=참여 중 모임 / 멘토=내가 개설한 모임 / 관리자=모니터링 대시보드
  - 탭3 **내정보** — 프로필(닉네임·관심사·소개)

대안(고려함): 쪽지를 4번째 탭으로. → 탭 과다·모바일 하단 폭 부담으로 헤더 아이콘 방식 우선.

- Reviewer: aidlc-product-lead-agent (iteration 3)
- Verdict: READY
- Findings:
  - (수정 확인 / 신청 설문 소유권) iteration 3의 교정 — "사전 신청 설문 문항은 멘토가 모임 개설 시 자유롭게 구성하고, 멘티는 신청 시 응답만 한다" — 이 네 지점에서 상호 모순 없이 일관되게 반영됨. 화면 7(모임 개설)에 "사전 설문 문항 [＋문항 추가] ← 멘토가 자유롭게 문항 구성(멘티 신청 시 응답)"으로 free-form 문항 빌더가 추가됨. 화면 3(신청 설문)은 제목이 "신청 설문 (멘토가 정의한 문항)"으로 바뀌고 "※ 문항 틀은 멘토가 모임 개설 시 정의(화면 7). 멘티는 신청 시 응답만 한다."는 주석으로 출처를 명시함. user-flow Flow A는 "신청 + 사전 설문 응답(문항은 멘토가 개설 시 자유롭게 구성)", Flow B는 "모임 정보 + 사전 설문 문항 입력 → 개설 신청"으로 멘토가 정의·멘티가 응답하는 역할 분리가 흐름상 분명함. developer/QA가 "설문 문항을 누가 만드는가"를 되묻지 않아도 될 수준.
  - (회귀 확인 / 도메인 규칙) iteration 2에서 검증된 항목이 모두 유지됨. 관리자 승인 4개 지점(① 개설 ② 시작 ③ 멘토 정상 완료 ④ 멘티 수료)이 화면 6 "승인 큐 (4종)"와 user-flow "승인·수료 도메인 규칙"·상태 전이도에 그대로 명시됨. 멘티 수료 = 시스템 자동 판정(출석률 80%) + 관리자 승인④(화면 6 "자동판정 확정", 화면 5 주석, Flow B "멘토 소관 아님"), 멘토 완료 인정 + 멘티 피드백 확인 한정(화면 5), 멘티 피드백을 멘토·관리자 모두 열람(화면 6 "멘티 피드백 열람", 도메인 규칙)이 일관됨.
  - (회귀 확인 / 완전성) 11개 Must proto-Unit 중 10개가 명시적 화면으로 매핑되고 3역할·모바일 웹뷰·코호트 러닝 결·수료 80% 기준이 유지됨. 이번 교정으로 proto-Unit #10(설문·피드백)의 신청 설문 측면은 화면 3·7 양쪽에서 소유권까지 명확해져 오히려 강화됨.
  - (비차단 / 완전성) proto-Unit #10의 과정 종료 후 **과정 설문** 화면과 멘토·관리자의 **멘티 피드백 확인** 화면은 여전히 전용 와이어프레임이 없음(흐름상 Flow A/B·화면 5·6 진입점으로 커버). refined-mockups에서 화면을 추가할 것.
  - (비차단 / 명료성) 관리자 승인 큐 ①~④의 상세 검토·반려 UI(반려 사유 입력 등)는 미정. 화면 6은 큐 건수·액션 라벨까지만 표현. refined-mockups에서 확정할 것.
  - (비차단 / 명료성) 상태 용어 정합성: 화면 1 필터 [모집중][진행중][마감][종료]와 user-flow 라이프사이클 [개설신청]→[모집중]→[진행중]→[종료] 사이에 "마감"·"개설신청" 표기가 어긋남. refined-mockups에서 상태 어휘를 통일할 것.
  - (비차단 / 포맷) 화면 5 ASCII 블록 종료 직후 멘토 주석 아래에 여닫는 code fence(```)가 중복되어 빈 코드블록이 남아 있음. 차단 사유는 아니나 refined-mockups 정리 시 제거 권장.
