# User Flows — learnKK (런크크)

<!-- 핵심 사용자 흐름(happy path). 출처: intent-statement, scope-document, intent-backlog. -->

`intent-statement.md`의 3역할과 `intent-backlog.md`의 proto-Unit을 흐름으로 연결한다. `scope-document.md` In-scope 여정 기준.

## 정보 구조 요약

```
가입/로그인
   │
   ├─ 탭1 모임(탐색) ── 모임 상세 ── (멘티) 신청+설문
   ├─ 탭2 내 러닝 ── 역할 적응형(멘티 참여중 / 멘토 개설 / 관리자 모니터링)
   └─ 탭3 내정보(프로필)
전역: [쪽지] 헤더 아이콘
```

## Flow A — 멘티 (신청 → 수료)

```
로그인 → [탭1 모임] 탐색·필터
      → 모임 상세(모집중) → 신청 + 사전 설문 응답(문항은 멘토가 개설 시 자유롭게 구성)
      → (모집 마감·확정) → [탭2 내 러닝] 참여 중 모임
      → 주차별: 공지 확인 · 자료실 열람 · (당일) 출석 체크 · 멘토와 쪽지
      → 전 주차 종료 → (시스템 자동) 출석률 80%↑ 시 수료 자동 인정
      → 과정 설문 작성
```

## Flow B — 멘토 (개설 → 완료 인정)

```
로그인 → [탭1] 개설(＋) → 모임 정보 + 사전 설문 문항 입력 → 개설 신청
      → (관리자 승인) → 정식 모임 → 모집·멘티 설문 열람
      → 모집 마감·인원 확정 → [탭2 내 러닝] 모임 관리
      → 주차별: 자료 업로드 · 공지 · (당일) 모임 시작/종료 · 멘티와 쪽지
      → 전 주차 종료 → (멘티 수료는 시스템 자동 판정 — 멘토 소관 아님)
      → 멘토: 모임 정상 완료 인정 신청 → (관리자 승인③)
      → 멘티 피드백(설문) 확인 (관리자도 열람 가능)
```

## Flow C — 시스템 관리자 (감독 → 수료 판단)

```
로그인 → [탭2 모니터링]
      → ① 개설 승인 큐 → 개설 모임 검토 → 승인/반려
      → ② 시작 승인 큐 → 모집 확정 모임의 진행 시작 승인
      → 진행 현황 모니터링(출석/수료 통계) · 멘티 피드백 열람
      → 특이사항 시 멘토/멘티에게 쪽지
      → ③ 멘토 완료 승인 큐 → 멘토의 정상 완료 인정 승인
      → ④ 멘티 수료 승인 큐 → 시스템 자동 판정된 멘티 수료 승인·확정
```

## 승인·수료 도메인 규칙

- **관리자 승인 4개 지점:** ① 모임 개설, ② 모임 시작, ③ 멘토 정상 완료, ④ 멘티 수료 완료. 각 지점은 관리자의 명시적 승인을 거친다.
- **멘티 수료:** 출석률 80% 기준으로 **시스템이 자동 판정**하며, 그 결과를 **관리자가 승인(④)** 하여 확정한다. 멘토는 멘티 수료를 인정하지 않는다.
- **멘토 완료:** 멘토가 모임 정상 완료를 인정 신청하고, **관리자가 승인(③)** 한다.
- **멘티 피드백(과정 설문):** 멘토가 확인하며, **관리자도 열람 가능**하다.

## 상태 전이 (모임 라이프사이클)

```
[개설신청] → (관리자 승인①) → [모집중] → (모집마감·인원확정)
   → (관리자 시작 승인②) → [진행중] → (전 주차 종료)
   → (시스템) 멘티 수료 자동 판정 · 과정 설문
   → 멘토 완료 인정 → (관리자 승인③ 멘토완료, ④ 멘티수료) → [종료·수료확정]
```
