# 요구사항 — 260827-seed-ux-bugfix

- **인텐트**: `260827-seed-ux-bugfix`
- **스코프**: bugfix (minimal depth / 최소 깊이)
- **프로젝트**: learnKK (브라운필드 — Java/Spring 백엔드, React/Vite 프론트엔드)
- **유형**: 두 건의 타겟 결함 수정 (시드 데이터 정합성 1건, 프론트엔드 UX 일관성 1건)

## 1. 의도 분석

사용자가 데모에서 두 건의 결함을 보고했으며, 원인은 이미 규명되어 있다.

1. **높음 — 수료 판정 시드가 80% 규칙 위반.** 데모 시드(`V12__seed_demo.sql`)가
   CS 스터디 멘티2를 `attended=3, total=4`(75%)인데 `COMPLETION_CANDIDATE`(수료 후보)로
   삽입한다. 이는 수료 규칙(`a*100 >= 80*S` → `300 >= 320` = 거짓)에 위배된다. 이렇게
   시드된 후보는 정상 compute→approve 흐름으로는 만들 수 없는 상태이며, 관리자가
   "수료 확정"을 누르면 규칙상 나올 수 없는 **"75% 수료확정"** 이 관리/운영현황 화면에
   표시된다.
2. **중간 — 모집중 목록 신청 버튼 상태 미반영.** 모집중 목록 최초 로드 시, 현재 멘티가
   이미 신청한 모임도 "신청" 버튼이 활성 상태로 표시된다. 이미 신청한 상태는 버튼을
   클릭한 뒤에야 나타난다. 목록 로드 시점에 신청 상태가 반영되지 않는 문제다.

## 2. 기능 요구사항

### FR-1 (높음) — 규칙에 맞는 수료 후보 시드
데모 시드에는 수료 자격을 의미하는 상태(`COMPLETION_CANDIDATE` 또는 `COMPLETED`)를 가지면서
`attended_count / total_scheduled` 비율이 80% 미만인 `mentee_completion` 행이 존재해서는
안 된다.

**선택된 조치(사용자 결정 Q1 = B):** CS 스터디 멘티2를 **4/4 진짜 후보**로 변경한다.
- 출석: 멘티2가 CS 스터디 **4개 세션 전체**에 출석(주차 1~3만이 아님).
- `mentee_completion`: 멘티2 행을 `COMPLETION_CANDIDATE`, `attended_count=4`,
  `total_scheduled=4`, `approved_at=NULL` 로 설정.
- 관련 주석을 4/4 후보로 갱신.
- 멘티1(4/4 수료확정), 멘티4(1/4 미수료)는 변경 없음. 결과적으로 시드는 후보 vs 확정이
  판정 상태만 다른 예시를 제공한다.
- **애플리케이션 로직 변경 없음**(`CompletionService.applyJudgement`는 정상).

### FR-2 (중간) — 모집중 목록 로드 시 신청 상태 반영
멘티가 모집중 목록을 조회할 때, 이미 신청한(신청 상태 `APPLIED`) 모임은 최초 로드 시점에
"이미 신청함"으로 표시되어야 한다 — 즉 클릭 없이도 신청 버튼이 비활성화되고
"신청완료"/"신청됨"으로 라벨링된다.
- 구현은 **프론트엔드 전용**: 목록 로드 시 현재 사용자가 멘티이면 기존
  `enrollmentsApi.listMine()` 로 본인 신청 내역을 조회하고, 상태가 `APPLIED` 인 모임 id
  집합을 만들어 모임별 신청 상태를 초기화한다.
- 비멘티(비로그인/멘토/관리자)에는 영향 없음.
- 신청 직후 "신청완료"로 전환되는 기존 동작은 그대로 유지되어야 한다.

## 3. 비기능 요구사항
- **NFR-1 (멱등성):** 시드 마이그레이션은 멱등성을 유지해야 한다
  (`ON CONFLICT DO NOTHING` / NOT EXISTS 가드 보존).
- **NFR-2 (무회귀):** 신청 상태 초기화를 제외한 기존 백엔드 수료 로직과 프론트엔드 신청
  흐름 동작은 변경되지 않는다.
- **NFR-3 (마이그레이션 정합성):** `V12__seed_demo.sql` 을 in-place 수정한다(재빌드 시
  초기화되는 데모/개발 시드 데이터). 새 마이그레이션 버전을 만들지 않는다.

## 4. 수용 기준
- **AC-1 (FR-1):** 신규 시드 적용 후, 상태가 (`COMPLETION_CANDIDATE`,`COMPLETED`) 인
  `mentee_completion` 행 중 `attended_count*100 < 80*total_scheduled` 인 행이 없어야 한다.
- **AC-2 (FR-1):** CS 스터디 멘티2는 출석 4건과 `4/4`·`COMPLETION_CANDIDATE`·
  `approved_at=NULL` 수료 행을 가진다.
- **AC-3 (FR-1):** 관리/운영현황 화면에서 80% 미만의 "수료확정"이 더 이상 나타날 수 없다.
- **AC-4 (FR-2):** 이미 신청한 모임이 목록에 있는 멘티로 모집중 목록을 최초 렌더링하면,
  해당 모임의 신청 컨트롤이 상호작용 없이 비활성/신청완료 상태로 표시된다.
- **AC-5 (FR-2):** 아직 신청하지 않은 모임에 신청하면 여전히 "신청완료"로 전환된다.
- **AC-6:** 프론트엔드 빌드/테스트와 백엔드 빌드가 통과한다.
