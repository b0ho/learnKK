# learnKK 수동 기능 테스트 시나리오

모든 도메인(U1~U8)을 **멘토 → 관리자 → 멘티** 흐름으로 직접 클릭하며 검증하는 시나리오입니다. 상단부터 순서대로 진행하면 모임 라이프사이클(개설→①승인→모집확정→②시작→③완료)과 각 부가 기능이 자연스럽게 이어집니다.

---

## 0. 사전 준비

| 항목 | 값 |
|---|---|
| 프론트 | http://localhost:5173 |
| 백엔드 | http://localhost:8080 |
| DB | PostgreSQL `localhost:5432` (db/user/pass = `learnkk`) |

**테스트 계정** (비밀번호 공통 `password123`)

| 닉네임 | 사번 | 역할 |
|---|---|---|
| `mentor1` | E1001 | MENTOR |
| `mentee1` | E1002 | MENTEE |
| `admin1` | E1003 | ADMIN |

> 로그인 후 각 역할은 하단 네비게이션(모임 / 내 러닝 / 쪽지 / 내정보)과 역할별 추가 메뉴를 봅니다.
> 여러 역할을 오갈 때는 로그아웃(내정보) 또는 시크릿창/다른 브라우저를 쓰면 편합니다.

**모임 상태 흐름 (참고)**

```
개설(PENDING_APPROVAL)
   └─①승인(T1)→ RECRUITING
                   └─모집확정(T3)→ READY_TO_START
                                      └─②시작(T5)→ IN_PROGRESS
                                                      └─③완료(T6)→ COMPLETED
   └─반려(T2)→ REJECTED      모집확정 취소(T4)→ CANCELLED
```

## 1. 인증 / 프로필 (U1·U2)

### 1-1. 회원가입 — (신규 계정 확인용, 선택)
- **역할**: 누구나 · **경로**: `/signup`
- 닉네임/비밀번호(8자+)/사번/역할(멘토 or 멘티) 입력 → 가입
- **기대**: 가입 성공 후 로그인 화면 이동. 관리자(ADMIN) 역할 선택지는 없음(가입 불가).
- **경계 확인**: 이미 쓰인 사번/닉네임으로 가입 → 오류(중복). 비밀번호 8자 미만 → 검증 오류.

### 1-2. 로그인
- **역할**: mentor1 / mentee1 / admin1 각각 · **경로**: `/login`
- **기대**: 세 계정 모두 로그인 성공 → `/meetings` 진입. 잘못된 비밀번호 → "닉네임 또는 비밀번호가 올바르지 않습니다".

### 1-3. 내 정보 / 프로필 수정
- **역할**: 아무 계정 · **경로**: `/me`
- 관심사 태그(최대 10개)·소개(500자 이하) 수정 → 저장
- **기대**: 저장 성공. 태그 11개/소개 500자 초과 시 검증 오류. 로그아웃 동작 확인.

---

## 2. 멘토 — 모임 개설 & 사전설문 문항 (U3)

> **로그인: `mentor1`**

### 2-1. 모임 개설
- **경로**: `모임` → `모임 개설`(`/meetings/new`) — 멘토만 노출
- 입력: 제목(필수), 주제, 기간(주차, 필수), 정원(필수), 형식, 모집기간, 초기 소개
- **기대**: 개설 성공. 상태 = **PENDING_APPROVAL**(승인 대기). `내 러닝`(운영 허브)에 방금 만든 모임이 "승인 대기"로 보임.

### 2-2. 사전설문 문항 빌더
- **경로**: `내 러닝` → 해당 모임 → 사전설문 문항 편집(또는 모임 상세)
- 문항 추가/순서/유형 지정 후 저장
- **기대**: 저장 성공. 참고: 문항은 특정 상태 이후 잠기며(`MEETING_QUESTIONS_LOCKED`) 그 뒤엔 수정 불가.

---

## 3. 관리자 — ① 개설 승인 (T1/T2)

> **로그인: `admin1`**

### 3-1. 승인 큐 확인
- **경로**: `모임` 상단 `개설 승인` 링크(`/admin/meetings`) — 관리자만 노출
- **기대**: 2-1에서 만든 PENDING_APPROVAL 모임이 큐에 보임.

### 3-2. 승인 (T1)
- 대상 모임 → **승인**
- **기대**: 상태 **RECRUITING**(모집중)으로 전이. `모임` 목록(모집중)에 노출됨.

### 3-3. (선택) 반려 (T2)
- 다른 테스트 모임을 하나 더 만들어 **반려** → 상태 **REJECTED**. 목록에서 사라짐.

---

## 4. 멘티 — 모집중 모임 신청 (U4)

> **로그인: `mentee1`**

### 4-1. 모집중 목록에서 신청
- **경로**: `모임`(`/meetings`) → 3-2에서 승인된 모임의 인라인 **신청** 버튼
- **기대**: 신청 성공. `내 러닝`에 신청 현황이 APPLIED로 보임.
- **경계 확인**:
  - 같은 모임 재신청 → "이미 신청한 모임입니다".
  - 정원 초과: 정원 1짜리 모임을 만들어 두 멘티가 신청하면 두 번째는 "모집 정원이 마감되었습니다".

### 4-2. 신청 취소
- **경로**: `내 러닝` → 신청 취소
- **기대**: 취소 성공(②시작 전까지 가능), 정원 복귀. 다시 신청 가능.
- (이후 시나리오를 위해 취소했다면 **다시 신청**해 APPLIED 상태로 둘 것.)

---

## 5. 멘토 — 신청자 확인 & 모집확정 준비 (U3·U4)

> **로그인: `mentor1`**

### 5-1. 신청자 목록
- **경로**: `내 러닝`(운영 허브) → 해당 모임의 신청자 목록/수
- **기대**: mentee1이 신청자로 보임(닉네임 노출).

---

## 6. 관리자 — 모집확정(T3) → ②시작(T5)

> **로그인: `admin1`** · **경로**: `개설 승인`(`/admin/meetings`)

### 6-1. 모집확정 (T3)
- 대상 모임 → **모집확정**(proceed=true)
- **기대**: 상태 **READY_TO_START**.
- (선택) 취소(T4): proceed=false + 사유 입력 → **CANCELLED**.

### 6-2. ②시작 (T5)
- 대상 모임 → **시작**
- **기대**: 상태 **IN_PROGRESS**. 이 시점부터 사전설문 응답·세션/출석이 열림.

---

## 7. 멘토 — 세션 일정 & 자료/공지 (U5·U6)

> **로그인: `mentor1`** · IN_PROGRESS 모임 대상

### 7-1. 세션 생성 (U5)
- **경로**: `내 러닝`(운영 허브) → 해당 모임 → 세션 관리 → 세션 추가
- 입력: 주차, 시작 시각(`scheduledAt`), 체크인 창 분(미입력 시 120분)
- **팁(출석 테스트용)**: 시작 시각을 **지금 시각**으로 잡으면 멘티가 바로 출석 가능(시간창 `[시작, 시작+창]`).
- **기대**: 세션 생성/목록 노출. 일정 변경(PUT)도 확인.

### 7-2. 자료실 · 공지 (U6)
- **경로**: 운영 허브 → 해당 모임 → `자료실 · 공지 관리`(`/meetings/{id}/content`)
- 주차별 게시글 작성(본문 필수), 첨부 업로드(허용 형식·20MB 이하), 공지 작성
- **기대**: 게시글/공지 생성. 첨부 다운로드 동작.
- **경계 확인**: 허용 안 되는 형식/20MB 초과 첨부 → 오류(형식/크기).

---

## 8. 멘티 — 자료 열람·사전설문·출석 (U6·U8·U5)

> **로그인: `mentee1`** · 참여(APPLIED) 중인 IN_PROGRESS 모임 대상

### 8-1. 자료 열람 (U6)
- **경로**: `내 러닝` → 해당 모임 → 자료실
- **기대**: 멘토가 올린 게시글/공지/첨부 열람 가능(참여자 권한).

### 8-2. 사전설문 응답 (U8)
- **경로**: `내 러닝` → 해당 모임 → `사전설문 응답`(`/meetings/{id}/survey-answer`)
- 문항 응답 후 제출(필수 문항 모두 응답)
- **기대**: 제출 성공. 재제출 시 갱신(문항당 1응답).
- **경계 확인**: 필수 문항 미응답 → 400. (②시작 전에는 응답 불가 = `PRESURVEY_NOT_OPEN`)

### 8-3. 출석 체크인 (U5)
- **경로**: `내 러닝` → 해당 모임 → 세션 출석
- 시간창 안에서 **출석** 클릭
- **기대**: 체크인 성공, 중복 클릭해도 멱등(1회). 출석율 갱신.
- **경계 확인**: 시간창 밖 → "출석 가능 시간이 아닙니다"(`ATTENDANCE_WINDOW_CLOSED`).

---

## 9. 멘토·멘티 — 쪽지 (U7)

### 9-1. 멘토 → 멘티 쪽지
- **로그인: `mentor1`** · **경로**: `쪽지`(`/messages`) → 새 쪽지 → 수신자 선택(자기 모임의 활성 멘티) → 전송
- **기대**: 스레드 생성·전송 성공.

### 9-2. 멘티 수신·답장
- **로그인: `mentee1`** · **경로**: `쪽지` → 안읽음 뱃지 확인 → 스레드 열람(읽음 처리) → 답장
- **기대**: 수신·읽음·답장 정상. 안읽음 수 갱신.
- **경계 확인**: 관계 없는 사용자에게 전송 시도 → 권한 오류(`MESSAGING_FORBIDDEN`), 자기 자신 전송 불가.

---

## 10. 멘티 — 과정 피드백 제출 (U8)

> **로그인: `mentee1`** · IN_PROGRESS(또는 COMPLETED) 모임

- **경로**: `내 러닝` → 해당 모임 → `피드백`(`/meetings/{id}/feedback`)
- 내용 작성 후 제출
- **기대**: 제출 성공(모임당 1건, 재제출 시 갱신).

---

## 11. 멘토/관리자 — 피드백·응답 열람 (U8)

- **멘토 로그인: `mentor1`** · **경로**: 운영 허브 → 해당 모임 → `피드백·사전설문 열람`(`/meetings/{id}/feedback-view`)
- **관리자 로그인: `admin1`** · 같은 경로 접근 가능
- **기대**: 멘티가 낸 피드백·사전설문 응답 열람 가능.
- **경계 확인**: 다른 모임 소유 멘토가 접근 → 403(`FEEDBACK_FORBIDDEN`). 멘티는 피드백 열람 경로 없음.

---

## 12. 수료 판정 & 확정 (U5)

### 12-1. 멘토 — 수료 후보 산출
- **로그인: `mentor1`** · **경로**: 운영 허브(또는 관리자 페이지) → 해당 모임 → 수료 판정(compute)
- **기대**: 출석율 기준 80% 이상 멘티가 **수료 후보(COMPLETION_CANDIDATE)** 로 표시. 출석율 = 출석/전체세션(세션 0이면 0).
  - (실제 후보가 되려면 8-3에서 예정 세션의 다수에 출석해 둬야 함.)

### 12-2. 관리자 — ④ 수료 확정
- **로그인: `admin1`** · **경로**: `개설 승인` → 해당 모임의 수료 현황 → 멘티 **수료 확정**
- **기대**: 해당 멘티 **COMPLETED**. 재확정 시도 → "이미 수료 확정된 멘티입니다".

---

## 13. 관리자 — ③ 모임 완료 (T6)

> **로그인: `admin1`** · **경로**: `개설 승인` → 대상 IN_PROGRESS 모임 → **완료**

- **기대**: 모든 예정 세션이 종료된 경우 상태 **COMPLETED**로 전이.
- **경계 확인**: 아직 끝나지 않은 세션이 있으면 409 `MEETING_SESSIONS_NOT_ENDED`.
  - 완료 테스트를 하려면 7-1에서 세션 시작 시각을 **과거**로 잡거나 체크인 창을 짧게 줘서 세션이 이미 종료되도록 만들 것.

---

## 14. Bolt 8 (U9, 미구현) — 참고

관리자 **종합 모니터링 / 승인 큐 통합 대시보드**(U9)는 아직 개발 전(Bolt 8)입니다. 현재 관리자 기능은 개별 승인/수료확정까지이며, 종합 모니터링 화면은 없습니다.

## 부록 A. 권한 경계 빠른 체크

| 시도 | 기대 |
|---|---|
| 멘티가 `/meetings/new` 접근 | 접근 불가(멘토 전용) |
| 멘티가 `/admin/meetings` 접근 | 접근 불가(관리자 전용) |
| 멘티가 `/meetings/{id}/feedback-view` 접근 | 접근 불가(멘토/관리자 전용) |
| 비참여 멘티가 남의 모임 자료실 접근 | 403 `CONTENT_FORBIDDEN` |
| 관리자 계정 가입 시도(`/signup`) | ADMIN 선택지 없음 / 거부 |

## 부록 B. 상태 리셋 (필요 시)

DB를 깨끗이 비우고 다시 테스트하려면(로컬 데이터 삭제됨):

```bash
docker exec learnkk-postgres psql -U learnkk -d learnkk -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public; GRANT ALL ON SCHEMA public TO learnkk;"
```

이후 백엔드를 재기동하면 Flyway가 V1~V8을 다시 적용합니다. 계정도 다시 만들어야 합니다(멘토/멘티는 가입, 관리자는 가입 후 DB에서 `UPDATE users SET role='ADMIN' WHERE nickname='admin1';`).
