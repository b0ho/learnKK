# learnKK 수동 기능 테스트 시나리오

모든 도메인(U1~U8)을 **멘토 → 관리자 → 멘티** 흐름으로 직접 클릭하며 검증하는 최종 시나리오입니다. 상단부터 순서대로 진행하면 모임 라이프사이클(개설→①승인→모집확정→②시작→③완료)과 각 부가 기능이 자연스럽게 이어지며, 그동안의 UX/동작 보정(1·2차 버그픽스)까지 각 단계에서 함께 확인합니다.

---

## 0. 사전 준비

| 항목 | 값 |
|---|---|
| 프론트 | http://localhost:5173 |
| 백엔드 | http://localhost:8080 |
| DB | PostgreSQL `localhost:5432` (db/user/pass = `learnkk`) |

### 0-1. 시드 계정 (Flyway V10·V11로 자동 생성)

백엔드를 기동하면 Flyway 마이그레이션이 아래 계정을 자동으로 만듭니다. **별도 회원가입 없이 바로 로그인**할 수 있습니다.

| 닉네임 | 사번 | 역할 | 비밀번호 |
|---|---|---|---|
| `admin` | ADMIN001 | ADMIN | `admin1234` |
| `멘토1` | MENTOR001 | MENTOR | `password123` |
| `멘토2` | MENTOR002 | MENTOR | `password123` |
| `멘티1` ~ `멘티7` | MENTEE001 ~ MENTEE007 | MENTEE | `password123` |

> ADMIN은 signup으로 가입할 수 없어(`ADMIN_SIGNUP_FORBIDDEN`) 시드로 제공됩니다. 시드 비밀번호는 개발용이며 운영 배포 전 반드시 변경 대상입니다.

### 0-2. 시드 데모 데이터 (Flyway V12·V13) — 상태별 즉시 점검용

V12/V13이 **모든 모임 상태**와 다양한 참여/출석/수료/설문/피드백 케이스를 미리 넣어 둡니다. 직접 만들기 번거로운 상태(반려/취소/정원 마감/완료됨 등)는 아래 시드 모임으로 즉시 확인하세요. (멱등 시드라 재기동/기존 데이터와 안전하게 공존)

| 모임 | 멘토 | 상태 | 참고 케이스 |
|---|---|---|---|
| 리액트 실전 스터디 | 멘토1 | IN_PROGRESS | 멘티1·2·3 참여, 세션 3개(1·2주차 완료·과거 / 3주차 미래), 출석 멘티1=2/2·멘티2=1/2·멘티3=0, 설문 2문항+멘티1·2 응답 |
| 완료된 CS 스터디 | 멘토1 | COMPLETED | 세션 4개 완료, 멘티 수료 = 멘티1 확정·멘티2 후보·멘티4 미수료, 피드백 멘티1·2, **멘토 수료 = 수료(COMPLETED)** |
| 모집중 알고리즘 | 멘토1 | RECRUITING | 멘티1·2·3 신청, 멘티4 취소(정원 여유) |
| 개설 대기 코틀린 | 멘토2 | PENDING_APPROVAL | 개설 승인 대기 |
| 시작 대기 도커 | 멘토2 | READY_TO_START | 멘티1·2 신청 |
| 정원 마감 파이썬 | 멘토2 | RECRUITING(마감) | 정원 2, 멘티5·6로 마감 → 신청 시 정원 마감 확인용 |
| 반려된 블록체인 | 멘토2 | REJECTED | 반려 사유 포함 |
| 취소된 UX 워크숍 | 멘토2 | CANCELLED | 모집 취소 사유 포함 |

> 로그인 후 각 역할은 하단 네비게이션(모임 / 내 러닝 또는 관리 / 쪽지 / 내정보)을 봅니다.
> 여러 역할을 오갈 때는 로그아웃(내정보) 또는 시크릿창/다른 브라우저를 쓰면 편합니다.

### 0-3. 공통 UI 동작 (내비게이션) — 아래 모든 단계에서 함께 확인

- **활성 탭 재클릭 새로고침**: 하단 네비에서 **현재 위치한 탭을 다시 누르면** 그 탭의 루트 화면으로 리셋되고 데이터가 재조회된다. 이미 루트에 있어도 무반응(no-op)이 아니라 재조회된다. (예: `모임` 상세로 들어간 뒤 하단 `모임` 재클릭 → 목록 루트로 이동 + 재조회)
- **뎁스 이동 시 '이전' 버튼**: 탭 루트가 아닌 하위(뎁스) 화면(모임 상세/자료실/스레드/설문/피드백 등)에서는 **우하단에 플로팅 '이전' 버튼**이 뜬다. 클릭 시 브라우저 히스토리상 직전 화면으로 이동(`navigate(-1)`)한다. 탭 루트(목록) 화면에서는 표시되지 않는다.

**모임 상태 흐름 (참고)**

```
개설(PENDING_APPROVAL)
   └─①승인(T1)→ RECRUITING
                   └─모집확정(T3)→ READY_TO_START
                                      └─②시작(T5)→ IN_PROGRESS
                                                      └─③완료(T6)→ COMPLETED
   └─반려(T2)→ REJECTED      모집확정 취소(T4)→ CANCELLED
```

## 1. 인증 / 프로필 (U1·U2)

### 1-1. 회원가입 — (신규 계정 확인용, 선택)
- **역할**: 누구나 · **경로**: `/signup`
- 닉네임/비밀번호(8자+)/사번/역할(멘토 or 멘티) 입력 → 가입
- **기대**: 가입 성공 후 로그인 화면 이동. 관리자(ADMIN) 역할 선택지는 없음(가입 불가).
- **경계 확인**: 이미 쓰인 사번/닉네임(예: 시드 `MENTOR001`/`멘토1`)으로 가입 → 오류(중복). 비밀번호 8자 미만 → 검증 오류.

### 1-2. 로그인
- **역할**: `멘토1` / `멘티1` / `admin` 각각 · **경로**: `/login`
- **기대**: 세 계정 모두 로그인 성공 → `/meetings` 진입. 잘못된 비밀번호 → "닉네임 또는 비밀번호가 올바르지 않습니다".

### 1-3. 내 정보 / 프로필 수정
- **역할**: 아무 계정 · **경로**: `/me`
- 관심사 태그(최대 10개)·소개(500자 이하) 수정 → 저장
- **기대**: 저장 성공. 태그 11개/소개 500자 초과 시 검증 오류. 로그아웃 동작 확인.

## 2. 멘토 — 모임 개설 & 사전설문 문항 (U3)

> **로그인: `멘토1`**

### 2-1. 모임 개설
- **경로**: `모임` → `모임 개설`(`/meetings/new`) — 멘토만 노출
- 입력: 제목(필수), 주제, 기간(주차, 필수), 정원(필수), 형식, 모집기간, 초기 소개
- **기대**: 개설 성공. 상태 = **PENDING_APPROVAL**(승인 대기). `내 러닝`(운영 허브)에 방금 만든 모임이 "승인 대기"로 보임.

### 2-2. 사전설문 문항 빌더
- **경로**: 개설 화면(`/meetings/new`) 하단 사전설문 빌더, 또는 개설 후 운영 허브(`내 러닝`) 모임 카드의 **`사전설문 문항 관리`** 진입점(`/meetings/{id}/questions-edit`)
- 문항 추가/순서/유형 지정 후 저장. 유형을 **선택(CHOICE)** 으로 바꾸면 "선택지 (쉼표로 구분)" 입력칸이 나옴.
- **선택지 쉼표 입력 확인**: 선택지에 `초급, 중급, 고급`을 타이핑 → 쉼표가 입력 도중 사라지지 않고 그대로 유지되고, 저장 시 3개 선택지로 분리 저장된다.
- **수정 허용 시점**: 개설 이후에도 운영 허브의 `사전설문 문항 관리`로 **모집확정(READY_TO_START)까지** 추가/수정 가능. **②시작(IN_PROGRESS)** 이후 저장 시 잠금 메시지(`MEETING_QUESTIONS_LOCKED`).

## 3. 관리자 — ① 개설 승인 (T1/T2)

> **로그인: `admin`**

### 3-1. 승인 화면 진입 & 목록 구조
- **경로**: 관리자는 하단 네비에 `내 러닝` 대신 **`관리`** 탭이 보임 → 클릭(`/admin/meetings`). (멘토/멘티에는 `관리` 없음)
- **기대**: 모임 ID를 입력해 조회하는 방식이 아니라, 처리 대기 모임이 **승인 유형별 영역**으로 나뉘어 목록으로 보임 — `개설 승인 대기` / `모집 확정 대기 (모집중)` / `시작 대기` / `완료 · 수료 판정 (진행중)` / `완료됨`.
- **섹션 헤더 확인**: 각 영역 제목 **앞에 단계 숫자(①②③④)가 붙지 않고**, 제목 옆 건수 `(n)` 표시도 없다(텍스트 라벨만). 2-1에서 만든 모임이 `개설 승인 대기` 영역에 보이고, 시드의 `개설 대기 코틀린`도 같은 영역에 함께 보인다. 각 카드에는 그 상태의 액션만 노출.

### 3-2. 승인 (T1) — 확인 후 실행
- 대상 모임 카드 → **승인** 클릭 → **확인 다이얼로그**가 뜸 → `확인`을 눌러야 실제 승인. `취소`면 상태 변화 없음.
- **기대**: 상태 **RECRUITING**(모집중)으로 전이. 목록에서 `모집 확정 대기 (모집중)` 영역으로 이동.

### 3-3. (선택) 반려 (T2)
- 다른 테스트 모임을 하나 더 만들어 **반려** → 사유 입력 다이얼로그에 사유 기입 후 확정 → 상태 **REJECTED**. (시드 `반려된 블록체인`으로 반려 결과 표시도 확인 가능)

### 3-4. 승인 되돌리기
- 방금 승인한 모집중 모임 카드 → **되돌리기** → 확인 다이얼로그 → `확인`
- **기대**: 직전 상태로 역전이(모집중→개설 승인 대기). 마찬가지로 시작대기→모집중, 진행중→시작대기, 완료→진행중도 되돌리기 가능. 반려/모집취소 모임에는 `되돌리기` 버튼이 없음.

### 3-5. 모임 목록 화면에는 관리 진입점 없음
- **경로**: 관리자로 `모임`(`/meetings`) 진입
- **기대**: 목록에 **'개설 승인' 같은 관리 진입 버튼이 노출되지 않는다**. 모든 관리 액션은 하단 `관리` 탭(`/admin/meetings`)에서만 수행한다.

## 4. 멘티 — 모집중 모임 신청 (U4)

> **로그인: `멘티1`**

### 4-1. 모집중 목록에서 신청
- **경로**: `모임`(`/meetings`) → 3-2에서 승인된 모임(또는 시드 `모집중 알고리즘`)의 인라인 **신청** 버튼
- **기대**: 신청 성공. `내 러닝`에 신청 현황이 APPLIED로 보임.
- **경계 확인**:
  - 같은 모임 재신청 → "이미 신청한 모임입니다".
  - 정원 마감: 시드 `정원 마감 파이썬`(정원 2, 이미 마감)에 신청 → "모집 정원이 마감되었습니다". (혹은 정원 1짜리 모임을 만들어 두 멘티가 신청)

### 4-2. 신청 취소 → 재신청
- **경로**: `내 러닝` → 신청 취소
- **기대**: 취소 성공(②시작 전까지 가능), 정원 복귀.
- **재신청 확인**: 취소 후 다시 `모임`에서 같은 모임에 **신청** → 성공(취소했던 신청이 재활성화됨). 이미 신청 상태에서 또 신청하면 "이미 신청한 모임입니다".
- (이후 시나리오를 위해 최종적으로 APPLIED 상태로 둘 것.)

### 5-1. 신청자 목록
- **경로**: `내 러닝`(운영 허브) → 해당 모임의 신청자 목록/수
- **기대**: 멘티1이 신청자로 보임(닉네임 노출).

## 6. 관리자 — 모집확정(T3) → ②시작(T5)

> **로그인: `admin`** · **경로**: `관리`(`/admin/meetings`)

### 6-1. 모집확정 (T3)
- `모집 확정 대기 (모집중)` 영역의 대상 모임 → **모집 확정** → 확인 다이얼로그 → `확인`
- **기대**: 상태 **READY_TO_START**(→ `시작 대기` 영역으로 이동).
- (선택) 취소(T4): **모집 취소** → 사유 입력 다이얼로그에 사유 기입 후 확정 → **CANCELLED**. (시드 `취소된 UX 워크숍`으로 취소 결과 표시도 확인 가능)

### 6-2. ②시작 (T5)
- `시작 대기` 영역의 대상 모임(또는 시드 `시작 대기 도커`) → **시작 승인** → 확인 다이얼로그 → `확인`
- **기대**: 상태 **IN_PROGRESS**(→ `완료 · 수료 판정 (진행중)` 영역). 이 시점부터 사전설문 응답·세션/출석이 열림.

## 7. 멘토 — 세션 일정 & 자료/공지 (U5·U6)

> **로그인: `멘토1`** · IN_PROGRESS 모임 대상(6-2에서 시작한 모임 또는 시드 `리액트 실전 스터디`)

### 7-1. 세션 생성 · 완료 처리 · 삭제 (U5)
- **경로**: `내 러닝`(운영 허브) → 해당 모임 → 세션 관리 → 세션 추가
- 입력: 주차, 시작 시각(`scheduledAt`), 체크인 창 분(미입력 시 120분)
- **팁(출석 테스트용)**: 시작 시각을 **지금 시각**으로 잡으면 멘티가 바로 출석 가능(시간창 `[시작, 시작+창]`).
- **기대**: 세션 생성/목록 노출. 일정 변경(시간 변경)도 확인.
- **레이아웃 확인**: 세션 목록에서 주차·시간 줄과 버튼 줄이 세로로 분리되어, 상태 전환/버튼 추가 시에도 버튼이 찌그러지지 않고 행 높이가 일정하다.
- **완료 처리**: 세션의 **완료 처리** 클릭 → `완료` 뱃지 표시. 완료된 세션은 시간과 무관하게 "종료"로 간주된다.
- **삭제**: 세션 **삭제** 클릭 → 확인창 승인 시 세션과 그 출석 기록이 함께 삭제(CASCADE)되고 출석율이 재계산된다. 다른 멘토/멘티는 권한 없음.

### 7-2. 자료실 · 공지 (U6)
- **경로**: 운영 허브 → 해당 모임 → **`자료실 · 공지 관리`** 버튼(`/my-learning/meetings/{id}/content`) — 텍스트 링크가 아니라 아이콘 달린 버튼으로 눈에 띄게 노출
- **탭 컨텍스트 확인**: '내 러닝'에서 이 진입점으로 들어가면 화면은 자료실로 이동하되 **하단 네비의 활성 탭이 '내 러닝'에 유지**되고 '모임'으로 바뀌지 않는다. 우하단 **'이전' 버튼**으로 운영 허브(내 러닝)로 복귀한다.
- 주차별 게시글 작성(본문 필수), 첨부 업로드(허용 형식·20MB 이하), 공지 작성
- **기대**: 게시글/공지 생성. 첨부 다운로드 동작.
- **경계 확인**: 허용 안 되는 형식/20MB 초과 첨부 → 오류(형식/크기).

## 8. 멘티 — 자료 열람·사전설문·출석 (U6·U8·U5)

> **로그인: `멘티1`** · 참여(APPLIED) 중인 IN_PROGRESS 모임 대상(시드 `리액트 실전 스터디`에 멘티1이 이미 참여 중)

### 8-1. 자료 열람 (U6)
- **경로**: `내 러닝` → 참여 모임 카드의 **`자료실 · 공지 보기`** 버튼(텍스트 링크가 아닌 아이콘 버튼) → 자료실(`/my-learning/meetings/{id}/content`)
- **탭 컨텍스트 확인**: '내 러닝'에서 진입해도 하단 활성 탭이 **'내 러닝'으로 유지**된다(‘모임’으로 하이라이트되지 않음). 우하단 '이전' 버튼으로 복귀.
- **기대**: 멘토가 올린 게시글/공지/첨부 열람 가능(참여자 권한).

### 8-2. 사전설문 응답 (U8)
- **경로**: `내 러닝` → 해당 모임 → `사전설문 응답`(`/my-learning/meetings/{id}/survey-answer`)
- 문항 응답 후 제출(필수 문항 모두 응답)
- **기대**: 제출 성공. 재제출 시 갱신(문항당 1응답). 진입 시 하단 탭 '내 러닝' 유지 + 우하단 '이전' 버튼.
- **경계 확인**: 필수 문항 미응답 → 400. (②시작 전에는 응답 불가 = `PRESURVEY_NOT_OPEN`)

### 8-3. 출석 체크인 (U5)
- **경로**: `내 러닝` → 해당 모임 → 세션 출석
- 시간창 안에서 **출석** 클릭
- **기대**: 체크인 성공, 중복 클릭해도 멱등(1회). 출석율 갱신.
- **출석완료 상태 유지 확인**: 한 번 출석한 세션은 **시간창이 닫힌 뒤 목록을 다시 조회해도 '출석완료'로 표시**된다(재방문·창 종료와 무관). 시드 `리액트 실전 스터디`의 멘티1은 1·2주차가 이미 '출석완료'로 보인다.
- **경계 확인**: 아직 출석 안 한 세션이 시간창 밖이면 → "출석 가능 시간이 아닙니다"(`ATTENDANCE_WINDOW_CLOSED`).

## 9. 멘토·멘티 — 쪽지 (U7)

### 9-1. 멘토 → 멘티 쪽지
- **로그인: `멘토1`** · **경로**: `쪽지`(`/messages`) → 새 쪽지 → 수신자 선택(자기 모임의 활성 멘티) → 전송
- **기대**: 스레드 생성·전송 성공.

### 9-2. 멘티 수신·답장 & 안읽음 뱃지
- **로그인: `멘티1`** · **경로**: `쪽지` → 하단 네비의 **안읽음 뱃지 수** 확인 → 스레드 열람(읽음 처리) → 답장
- **기대**: 수신·읽음·답장 정상.
- **뱃지 즉시 갱신 확인**: 안읽음 스레드를 열람해 읽음 처리되면 하단 네비의 **안읽음 카운트가 즉시 재조회되어 줄어들거나(0이면) 사라진다**.
- **경계 확인**: 관계 없는 사용자에게 전송 시도 → 권한 오류(`MESSAGING_FORBIDDEN`), 자기 자신 전송 불가.

## 10. 멘티 — 과정 피드백 제출 (U8)

> **로그인: `멘티1`** · IN_PROGRESS(또는 COMPLETED) 모임

- **경로**: `내 러닝` → 해당 모임 → `피드백`(`/my-learning/meetings/{id}/feedback`)
- **탭 컨텍스트 확인**: '내 러닝'에서 진입 시 하단 활성 탭 '내 러닝' 유지 + 우하단 '이전' 버튼으로 복귀.
- 내용 작성 후 제출
- **기대**: 제출 성공(모임당 1건, 재제출 시 갱신).

## 11. 멘토/관리자 — 피드백·응답 열람 (U8)

- **멘토 로그인: `멘토1`** · **경로**: 운영 허브(내 러닝) → 해당 모임 → `피드백·사전설문 열람`(`/my-learning/meetings/{id}/feedback-view`)
- **관리자 로그인: `admin`** · 같은 화면 접근 가능
- **기대**: `과정 피드백`과 `사전설문 응답`이 **별도 섹션(헤더)** 으로 분리되어 표시된다(한 카드에 혼재 안 됨). 각 섹션은 비었을 때 고유 안내 메시지를 표시.
- **사전설문 응답에 문항 표시 확인**: 사전설문 응답 섹션의 각 항목이 **"문항 텍스트 + 응답 값"** 형태로 렌더되어 어떤 질문에 대한 답인지 식별된다(예: 시드 `리액트 실전 스터디` → "참여 동기를 알려주세요." + 응답, "현재 실력 수준은?" + 초급/중급).
- **경계 확인**: 다른 모임 소유 멘토가 접근 → 403(`FEEDBACK_FORBIDDEN`). 멘티는 피드백 열람 경로 없음.

## 12. 수료 판정 (U5) — 멘티 수료 & 멘토 수료

> **로그인: `admin`** · **경로**: `관리`(`/admin/meetings`) → `완료 · 수료 판정 (진행중)` 또는 `완료됨` 영역의 해당 모임 카드

### 12-1. 멘티 수료 후보 산출 & 확정
- 카드의 **`수료 판정`** 영역 → **수료 판정 실행**(compute)
- **기대**: 출석율 기준 80% 이상 멘티가 **수료 후보(COMPLETION_CANDIDATE)** 로 표시. 출석율 = 출석/전체세션(세션 0이면 0). 각 후보를 **수료 확정** → 해당 멘티 **COMPLETED**. 재확정 시도 → "이미 수료 확정된 멘티입니다".
  - (실제 후보가 되려면 8-3에서 예정 세션의 다수에 출석해 둬야 함. 시드 `완료된 CS 스터디`는 멘티1=확정·멘티2=후보·멘티4=미수료가 이미 반영되어 있어 즉시 확인 가능.)

### 12-2. 멘토 수료 판정 — 관리자가 판단
- 같은 카드의 **`멘토 수료 판정`** 영역 → 현재 상태 뱃지(`판정 전`/`수료`/`미수료`)와 **수료 / 미수료** 두 버튼
- **기대**: 멘티 수료(출석 80% 자동 판정)와 **별개로**, 관리자가 모임의 멘토에 대해 **수료/미수료를 판단만으로** 판정한다(자동 계산 없음). 버튼 클릭 시 뱃지가 갱신된다.
- **권한/상태**: 관리자 전용, IN_PROGRESS/COMPLETED 모임에서만 노출. 시드 `완료된 CS 스터디`의 멘토는 이미 `수료`로 판정되어 있음.

## 13. 관리자 — ③ 모임 완료 (T6)

> **로그인: `admin`** · **경로**: `관리`(`/admin/meetings`) → `완료 · 수료 판정 (진행중)` 영역의 대상 모임 → **완료 처리** → 확인 다이얼로그 → `확인`

- **기대**: IN_PROGRESS 모임이 **COMPLETED**로 전이. `완료됨` 영역으로 이동.
- **세션 종료 게이트 없음 확인**: 예정 세션이 **아직 모두 종료되지 않았더라도** 완료 처리가 가능하다(세션 미종료로 차단하지 않음). 확인 다이얼로그에도 "세션이 모두 종료되어야" 같은 전제 문구가 없다.
- **경계 확인**: IN_PROGRESS가 아닌 상태에서 완료 시도 → 409 `MEETING_INVALID_TRANSITION`.

## 14. Bolt 8 (U9, main 기준 미구현) — 참고

관리자 **종합 모니터링 / 승인 큐 통합 대시보드**(U9)는 `main` 기준 아직 개발 전(별도 `bolt8` 브랜치에서 진행)입니다. `main`의 관리자 기능은 개별 승인/수료 판정/완료 처리까지이며, 종합 모니터링 화면은 없습니다.

## 부록 B. 상태 리셋 (필요 시)

DB를 깨끗이 비우고 다시 테스트하려면(로컬 데이터 삭제됨):

```bash
docker exec learnkk-postgres psql -U learnkk -d learnkk -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public; GRANT ALL ON SCHEMA public TO learnkk;"
```

이후 백엔드를 재기동하면 Flyway가 **V1~V13**을 다시 적용합니다. 이때 **시드 계정(admin·멘토1~2·멘티1~7)과 데모 데이터(모든 상태 모임·참여·세션·출석·수료·설문·피드백)가 자동으로 다시 생성**되므로, 계정을 수동으로 만들 필요가 없습니다(관리자 포함). 시드는 멱등(ON CONFLICT / NOT EXISTS)이라 기존 데이터가 있어도 안전하게 공존합니다.
