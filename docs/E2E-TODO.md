## 우선순위: 높음 (모순 — 데모/규칙 신뢰성)

- [ ] **수료 판정 시드가 80% 규칙 위반** — `backend/src/main/resources/db/migration/V12__seed_demo.sql`
  - 현상: "완료된 CS 스터디"의 멘티2를 `attended=3, total=4`(75%)인데 `COMPLETION_CANDIDATE`(수료 후보)로 삽입. 주석도 "멘티2 = 3/4(수료 후보)".
  - 모순: 규칙 `a*100 >= 80*S` → `300 >= 320 = false`. 즉 3/4는 후보가 될 수 없음(앱의 `CompletionService.applyJudgement`도 동일 계산).
  - 부작용: 후보로 시드되어 있어 관리자가 "수료 확정" 가능 → 화면에 규칙상 나올 수 없는 **"75% 수료확정"** 표시(관리 페이지·운영현황 상세). 정상 흐름(compute→approve)으로는 재현 불가.
  - 조치안: 3/4는 `NOT_COMPLETED`로 시드하거나, "후보" 예시를 4/5(80%)로 변경. (앱 로직은 수정 불필요)
